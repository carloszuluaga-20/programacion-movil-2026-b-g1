# 2. Backlog priorizado

El backlog contiene las principales historias de usuario necesarias para desarrollar la primera versión de la aplicación.

Las historias se organizan según su prioridad dentro del MVP.

## Historias de usuario

### HU-01 - Consultar horario de clases

**Como** estudiante,  
**quiero** consultar mi horario de clases,  
**para** saber qué materias tengo y en qué momento debo asistir.

**Prioridad:** Alta

**Criterios de aceptación:**

- El estudiante debe poder visualizar las materias registradas.
- Cada materia debe mostrar su horario correspondiente.
- La información debe mostrarse de forma clara y ordenada.

---

### HU-02 - Consultar información de materias

**Como** estudiante,  
**quiero** consultar la información de mis materias,  
**para** conocer los datos principales de cada una.

**Prioridad:** Alta

**Criterios de aceptación:**

- El estudiante debe poder visualizar una lista de materias.
- Debe ser posible seleccionar una materia.
- Al seleccionar una materia se debe mostrar su información.

---

### HU-03 - Registrar notas

**Como** estudiante,  
**quiero** registrar las notas obtenidas en una materia,  
**para** llevar un control de mi rendimiento académico.

**Prioridad:** Alta

**Criterios de aceptación:**

- El estudiante debe poder seleccionar una materia.
- Debe poder ingresar una nota.
- La nota debe quedar asociada a la materia correspondiente.
- La nota registrada debe poder consultarse posteriormente.

---

### HU-04 - Consultar notas

**Como** estudiante,  
**quiero** consultar las notas registradas,  
**para** revisar mi rendimiento en cada materia.

**Prioridad:** Alta

**Criterios de aceptación:**

- El estudiante debe poder visualizar las notas de cada materia.
- Las notas deben mostrarse de manera organizada.
- Cada nota debe estar relacionada con su materia correspondiente.

---

### HU-05 - Navegar entre las pantallas principales

**Como** estudiante,  
**quiero** navegar entre las diferentes secciones de la aplicación,  
**para** acceder fácilmente al horario, materias y notas.

**Prioridad:** Media

**Criterios de aceptación:**

- El usuario debe poder acceder a la pantalla de inicio.
- Desde la aplicación debe poder acceder a materias y notas.
- La navegación debe ser sencilla y fácil de entender.

## Priorización del backlog

| ID | Historia de usuario | Prioridad |
|---|---|---|
| HU-01 | Consultar horario de clases | Alta |
| HU-02 | Consultar información de materias | Alta |
| HU-03 | Registrar notas | Alta |
| HU-04 | Consultar notas | Alta |
| HU-05 | Navegar entre pantallas | Media |

## Relación con el MVP

Las historias de prioridad alta corresponden directamente a las funciones principales definidas para el MVP.

La navegación es una funcionalidad de apoyo necesaria para facilitar el acceso a las diferentes secciones de la aplicación.
